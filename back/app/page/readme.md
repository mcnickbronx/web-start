# Модуль «Страницы»
Как устроен модуль · 21.10.2026

Страницы сайта и блог: рубрики, статьи, отдельные страницы вроде «О компании»,
SEO-поля и адреса для `sitemap.xml`. Тексты пишутся в админке в Markdown, сайт
получает готовый HTML.

Модуль необязательный. Подключение — строка `"page"` в `INSTALLED_APPS` и `migrate`.
Удаление — сначала `migrate page zero`, потом строка и папка: если просто удалить
папку, таблицы останутся в базе, а Django про них забудет.

## Адреса на сайте

| Что | Адрес |
|---|---|
| Рубрика со списком статей | `/{слаг рубрики}` |
| Статья блога — страница с рубрикой | `/{слаг рубрики}/{слаг}` |
| Отдельная страница — без рубрики | `/{слаг}` |

Рубрики и отдельные страницы делят корень сайта, поэтому слаг уникален сразу
у рубрик и страниц: админка не даст занять адрес дважды.

Корень сайта делят ещё бэкенд и фронт. Правило простое: **адрес совпал со страницей
фронта — показывается страница фронта**, страница из админки по нему не откроется.
Бэкенду о страницах фронта знать не нужно — у каждого сайта они свои. Редактору: если
страница из админки не открывается, а на её месте другая — у сайта уже есть страница
с таким адресом, смените слаг.

Не отдаются только адреса, до сайта не доходящие вовсе: бэкенд (`admin`, `api`, `static`,
`media`) и служебный адрес Nuxt (`_nuxt`). Файлы вроде `sitemap.xml` и `robots.txt` в списке
не нужны: в слаге не бывает точки.

## Редиректы

Адрес страницы на сайте поменялся — старый не должен отдавать 404: на него ведут ссылки
с других сайтов, закладки и поиск. Поэтому старый адрес ведёт на новый постоянным редиректом
(301): посетитель попадает на новую страницу, поисковик переносит на неё позиции.

- **Сам.** Сменили слаг опубликованной страницы или видимой рубрики — при сохранении старый
  адрес записывается в «Страницы → Редиректы». Адрес черновика нигде не стоит — его
  не запоминаем. Статьям при смене рубрики ничего не нужно: статья ищется по своему слагу,
  а неверную рубрику в адресе сайт исправляет сам.
- **Руками** — когда на движок переезжает старый сайт: старый адрес → новый. Ссылку можно
  вставить целиком, с доменом — сохранится путь. «/» в конце не важен, параметры не учитываются:
  `/index.php?id=5` и `/index.php?id=6` — один адрес.
- **Живая страница важнее.** Сайт спрашивает о редиректе, только когда по адресу ничего нет:
  редирект с адреса, где есть страница, не сработает.
- **По кругу не водит.** Адрес менялся несколько раз — все старые ведут сразу на последний;
  вернули прежний — редирект с него удаляется. Руками нельзя вести на адрес, с которого
  уже есть редирект: админка подскажет конечный.

## Как пользоваться админкой

Раздел «Страницы»:
- **Рубрики** — название, описание, порядок в меню. Выключенная рубрика скрывает
  с сайта и себя, и свои статьи. Рубрику со статьями удалить нельзя — сначала
  перенесите или удалите статьи.
- **Страницы** — и статьи, и отдельные страницы. Рубрика выбрана — это статья блога,
  не выбрана — отдельная страница.
- **Картинки** — всё, что загружено: обложки и картинки из текстов.
- **Редиректы** — старые адреса и куда они ведут, см. выше.

Поля страницы, которые можно не заполнять:
- **слаг** — соберётся из заголовка латиницей при сохранении; адрес занят — с номером: `-2`, `-3`;
- **анонс** — соберётся из начала текста;
- **дата публикации** — проставится в момент, когда отмечено «Опубликовано».
  Дата в будущем — страница появится на сайте в этот момент сама;
- **SEO-заголовок и описание** — сайт получит заголовок и анонс.

«Показывать поисковикам» выключено — страница остаётся на сайте, но закрыта
от индексации и не попадает в sitemap.

## Редактор текста

Два режима — визуальный и Markdown, вкладками внизу редактора. Текст можно вставлять
из Word и Google Docs: списки, абзацы и лишние пробелы из них приводятся в порядок
при сохранении. В базе остаётся исходный текст, HTML собирается заново при каждом
сохранении.

Картинку можно вставить из буфера или перетащить в текст — она загрузится сама.
Обложка загружается кнопкой «+» рядом с полем. Картинки шире 1600 пикселей (`PAGE_IMAGE_WIDTH_MAX`)
ужимаются, всё, кроме gif, переводится в webp: фото с телефона на 8 МБ иначе
замедлит страницу. Поворот, который телефон записал в снимок, учитывается при загрузке —
вертикальное фото не ляжет на бок. Файл, который не открывается как картинка,
не загрузится ни в «Картинки», ни в текст — даже с расширением картинки.

Из текста вырезается всё, что может быть опасным: скрипты, встроенные фреймы,
стили. Вставить на страницу виджет или видео кодом не получится — это сознательное
ограничение.

Удалённая картинка пропадает с диска. Если она стояла в тексте страницы, там
останется пустое место — перед удалением проверьте, где картинка используется.

## API

Всё без авторизации, только чтение, адреса — `/api/page/...`:

| Эндпоинт | Зачем |
|---|---|
| `category/info` | рубрики для меню и фильтра ленты |
| `list` | лента блога: фильтр по рубрике, поиск, сортировка |
| `detail/{slug}` | страница или статья целиком |
| `resolve/{slug}` | что лежит по адресу `/{slug}`: рубрика, страница или ничего |
| `redirect?path=…` | куда переехал старый адрес: сайт спрашивает, когда по адресу ничего нет |
| `sitemap` | адреса для `sitemap.xml` |

- На сайт попадает только видимое: опубликовано, дата публикации наступила,
  рубрика не скрыта. Всё остальное — 404, как будто страницы нет.
- В ленте только статьи с рубрикой. Отдельные страницы открываются по адресу.
- SEO-поля приходят уже заполненными: если в админке пусто, там заголовок и анонс.
- У каждой записи есть `path` — готовый адрес на сайте. Собирать его на фронте не нужно.
- `resolve` нужен странице фронта вида `/{slug}`: одним запросом понять, рубрику
  показывать или страницу.
- `sitemap` отдаёт адреса без домена. Фронт добавляет домен, склеивает со своими
  страницами и отдаёт `/sitemap.xml`. Так же свой `sitemap` может отдавать любой
  модуль с публичными адресами.

Адреса картинок — от корня сайта (`/media/...`). Если фронт живёт на другом домене,
`/media/` нужно проксировать на бэкенд.

## Настройки

В `.env` проекта; нет строки — значение по умолчанию ([как устроено](../core/readme.md#настройки-модулей)).

| Настройка | По умолчанию | Что |
|---|---|---|
| `PAGE_IMAGE_WIDTH_MAX` | 1600 | картинки шире ужимаются до этой ширины, в пикселях, не меньше 100 |
| `PAGE_IMAGE_SIZE_MAX_MB` | 15 | размер загружаемой картинки, не больше 50: файл читается в память целиком |

Ширина действует на новые загрузки: уже загруженные картинки не пересжимаются.

## Если поменялся рендер

HTML хранится готовым и сам не пересобирается. После изменения правил рендера
Markdown — `manage.py rerender_pages`, команда пересоберёт все страницы.

## Шпаргалка

- Рубрика выбрана — статья блога, нет — отдельная страница в корне сайта.
- Пустые слаг, анонс, дата публикации и SEO заполнятся сами.
- На сайт — только опубликованное, с наступившей датой, из видимой рубрики.
- Адрес совпал со страницей фронта — показывается страница фронта; бэкенду о ней знать не нужно.
- Сменили слаг опубликованного — старый адрес ведёт на новый сам; адреса старого сайта — «Редиректы» руками.
- Удалить модуль — `migrate page zero`, потом строку в `INSTALLED_APPS` и папку.
