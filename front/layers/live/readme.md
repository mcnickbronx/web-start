# Слой live
Как устроен слой · 24.10.2026

Живые события в кабинете: сервер сам сообщает открытой странице, что что-то произошло — заказ
оплачен, пришло сообщение, отчёт готов. Пара к модулю `live` бэкенда (`back/app/live`).
Зависит только от `core`; токен после 4401 обновляет слой `user`.

## Как подключить

В движок сайтов слой не входит. Сайт с кабинетом добавляет его третьей строкой `extends`
с тем же тегом, без `install` (почему — в [readme слоя user](../user/readme.md#как-подключить)):

```ts
extends: [
  ['gh:mcnickbronx/web-start/front#v2.4.0', { install: true }],
  'gh:mcnickbronx/web-start/front/layers/user#v2.4.0',
  'gh:mcnickbronx/web-start/front/layers/live#v2.4.0',
],
```

На бэкенде сайта должен быть включён модуль `live`: без него соединение не откроется, и слой будет
переподключаться с паузой до 30 секунд. Поэтому слой — вместе с модулем.

## Как пользоваться

```ts
const live = useLive()
live.on('order_paid', () => refresh())                 // подписка; в компоненте снимается сама
watch(live.status, (status) => {                       // переподключились — перечитать данные
  if (status === 'ready') refresh()
})
```

Пример — каркас кабинета демо-сайта `.playground/app/layouts/lk.vue`: значок «на связи» и тост
на событие `notice` (с бэкенда — `hub.send(user_id, {"type": "notice", "title": "…"})`).

- **Событие** — объект с полем `type` и полями, которые задаёт модуль бэкенда, который его шлёт.
  Событие не хранится: что пришло, пока соединения не было, — потеряно. Поэтому событие — сигнал
  «что-то изменилось», а данные страница берёт из API: после события и после каждого `ready`.
- **`live.status`** — `idle` (нет входа или закрыли), `connecting` (открываем или ждём паузу после
  обрыва), `ready` (на связи), `unauthorized` (сервер не принял токен и после обновления — нужен вход).
- **Одно соединение на вкладку**, сколько бы компонентов ни звали `useLive()`. Открывается при первом
  вызове, если есть access-токен; выход — закрывается; вход (и другим пользователем) — новое соединение
  с новым токеном. Работает только в браузере: на сервере Nuxt `useLive()` ничего не делает.

## Протокол

Как в модуле `live` бэкенда:

- Адрес — `apiBase` + `/api/live/ws`, `http` → `ws`, `https` → `wss`.
- Первое сообщение — `{"type": "auth", "token": "<access>"}`, ответ — `{"type": "ready"}`. Токен не
  в адресе: адрес пишут журналы uvicorn и Traefik.
- Код закрытия **4401** — токен не подошёл: слой один раз обновляет токен (слой `user`, по куке refresh)
  и сразу подключается заново; второй 4401 подряд или обновить нечем — `unauthorized`, без переподключения;
  обновление не вышло — слой `user` забывает токен, соединение закрывается — `idle`.
- Обрыв (любой другой код) — переподключение через 1, 2, 5, 10, 30, 30… секунд; после `ready` паузы
  снова с 1 секунды.

## Что стоит знать

- **Соединение держит место в лимите Traefik**: не больше 150 одновременных запросов с адреса
  ([деплой](../../../back/docs/deploy.md#ограничение-частоты-запросов)), а открытое соединение — запрос,
  который длится, пока открыта вкладка. Отсюда одно соединение на вкладку, а не на компонент.
- Логика соединения — `app/utils/live-connection.ts`, без Vue и Nuxt, с тестами в `tests/`;
  `useLive()` — обёртка над ней. Договор с сайтом — только `useLive()`, `on` и `status`.

## Шпаргалка

- `useLive().on(тип, обработчик)` — событие; `useLive().status` — `ready`, значит на связи.
- После события и после каждого `ready` — данные заново из API.
- Подключение — третьей строкой `extends`; на бэкенде — модуль `live`.
