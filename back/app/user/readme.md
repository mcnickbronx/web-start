# Модуль «Пользователи»
Как устроен модуль · 21.10.2026

Пользователь с логином по email, JWT-авторизация API, регистрация с кодом подтверждения,
смена и сброс пароля. Модель пользователя одна на проект — она же в админке.

## Авторизация

Два токена: короткий access и долгий refresh. Подписаны `JWT_SECRET_KEY`,
отдельным от ключа Django: смена одного не разлогинивает другое.

Сроки — в `.env` проекта (см. [настройки](#настройки)), по умолчанию сутки и 30 дней. Кабинету
клиента подходят сутки и месяц, CRM сотрудников — покороче, приложению — подольше. Токены, выданные
раньше, живут по старому сроку, пока устройство не продлит вход: продлённая кука — уже на новый срок.
Срок refresh сократили — сессии, где не заходили дольше нового срока, удалит следующий вход
пользователя, и их токены перестанут работать.

Access приходит в ответе, клиент шлёт его в заголовке `Authorization: Bearer`. Refresh бэкенд
в ответ не отдаёт, а кладёт в куку `httpOnly` для одного адреса — `/api/user/refresh`: скрипты
страницы её не видят. Поэтому сайт входит из браузера прямо в API, с `credentials: 'include'`,
и сайт с бэкендом — на одном домене (бэкенд — поддомен сайта): куку с чужого домена браузер
не пришлёт.

**Каждый вход — сессия в базе** (устройство, IP, время входа и последней активности), её номер
зашит в оба токена. Токен действует, пока жива его сессия, поэтому выход срабатывает сразу,
а не когда истечёт access:

- выход удаляет сессию этого устройства;
- «выйти на всех устройствах», смена и сброс пароля — все сессии пользователя;
- из списка «где я вошёл» можно завершить любое другое устройство;
- в админке у пользователя видны его сессии — удалить сессию значит выйти на том устройстве.

Проверка токена, как и раньше, — один запрос к базе: сессия вместе с пользователем.
Refresh продлевается при каждом обновлении access: кто заходит, не вылетит,
а сессия без активности дольше срока refresh удаляется при следующем входе пользователя.

Как закрыть свой эндпоинт:

```python
from user.auth import CurrentUser, OptionalUser

@router.get("/orders")
async def orders(user: CurrentUser): ...   # 401 без токена
```

`CurrentUser` — без действующего токена сразу 401. `OptionalUser` — гость приходит как `None`.
`CurrentSession` — сессия этого устройства, пользователь в ней — `session.user`.

Правила, которые заложены в проверку токена:

- Пароли проверяются механизмом Django: пароль, заданный в админке, работает в API, и наоборот.
- Refresh-токен не принимается вместо access, хотя живёт дольше.
- Смена пароля — в том числе в админке — отзывает все ранее выданные токены: бэкенд
  сравнивает время выпуска токена и время последней смены пароля.
- Неактивный пользователь не войдёт и не получит новый access.

## Эндпоинты

| Эндпоинт | |
|---|---|
| `POST /api/user/register` | регистрация, код подтверждения на почту |
| `POST /api/user/activate` | активация по коду и сразу вход |
| `POST /api/user/activate/resend` | выслать код ещё раз — по умолчанию не чаще раза в минуту |
| `POST /api/user/pair` | вход: access в ответе, refresh — в куке |
| `POST /api/user/refresh` | новый access по куке |
| `POST /api/user/logout` | выход на этом устройстве |
| `POST /api/user/logout/all` | выход на всех устройствах |
| `GET /api/user/session/list` | где я вошёл: устройства, это — `is_current` |
| `DELETE /api/user/session/{id}` | выйти на другом устройстве |
| `GET`/`PATCH` `/api/user/me` | профиль |
| `POST /api/user/password/change` | смена пароля |
| `POST /api/user/password/reset` | забыли пароль: код на почту |
| `POST /api/user/password/reset/confirm` | новый пароль по коду |

Подробности параметров — в Swagger, `/api/docs`.

## Что стоит знать

- Email везде приводится к нижнему регистру: `User@Mail.ru` и `user@mail.ru` — один аккаунт.
  Это работает и в API, и в админке.
- Код подтверждения из шести цифр по умолчанию живёт 30 минут, повторно высылается не чаще раза в минуту:
  раньше — 406 «повторите через N сек». На ввод по умолчанию даётся 5 попыток, дальше код сгорает — иначе его можно подобрать перебором.
  Счётчик попыток виден в админке, в блоке «Код подтверждения», и сбрасывается при выдаче нового кода.
- Смена и сброс пароля завершают все сессии, поэтому в ответе сразу новый access и новая кука
  для этого устройства, а остальные выходят.
- Мобильное приложение работает с той же кукой: HTTP-клиент приложения хранит её и шлёт сам.
  На iOS и в React Native это так по умолчанию, на Android (OkHttp) и во Flutter — включить
  сохранение кук в клиенте, это стандартная настройка.
- Регистрация создаёт неактивного пользователя. Активным он становится после ввода кода.
- Зарегистрирован ли email, по ответам узнать можно: регистрация называет занятый адрес, активация —
  уже активированный аккаунт, повторный запрос кода в ту же минуту получает 406. Прятать это —
  значит отвечать неправду: «код отправлен», когда письма нет, — и человек, у которого кончились
  попытки, ждал бы письмо, которое не придёт. Перебор адресов сдерживает лимит частоты на прокси.
- Письмо с кодом уходит фоновой задачей. Локально, без Redis, оно печатается в консоль —
  так настроена почта в шаблоне `.env.txt`.

## Настройки

В `.env` проекта; нет строки — значение по умолчанию ([как устроено](../core/readme.md#настройки-модулей)).

| Настройка | По умолчанию | Что |
|---|---|---|
| `USER_JWT_ACCESS_LIFETIME_HOURS` | 24 | срок access, в часах; не длиннее refresh |
| `USER_JWT_REFRESH_LIFETIME_DAYS` | 30 | срок refresh, в днях: столько можно не заходить и не войти заново |
| `USER_CONFIRMATION_CODE_LIFETIME_MINUTES` | 30 | сколько живёт код подтверждения |
| `USER_CONFIRMATION_CODE_RESEND_SECONDS` | 60 | новое письмо с кодом — не чаще; от 30 и меньше срока кода |
| `USER_CONFIRMATION_CODE_ATTEMPTS` | 5 | попыток ввести код, не больше 10: больше — и 6 цифр подбираются перебором |

## Шпаргалка

- Закрыть эндпоинт авторизацией — `user: CurrentUser` в его параметрах.
- Пароль меняется только через сервис или админку, в обоих случаях старые токены перестают работать.
- Сроки токенов и кодов — `USER_*` в `.env`, значения по умолчанию — в `conf.py` модуля.
- Проверка токена — `auth.py`, логика регистрации и паролей — `services.py`, письмо — `tasks.py`.
