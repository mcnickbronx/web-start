# Фронт web-start

**Движок сайтов на Nuxt 4** — фронтовая половина `web-start`, пара к бэкенду
из [`../back`](../back/readme.md). Общее для всех сайтов — формы, блог, страницы из админки, SEO,
карта сайта — живёт здесь и выходит версиями. Каждый сайт — отдельный репозиторий
со своим дизайном, который подключает движок одной строкой.

Движок собран из **слоёв** — так же, как бэкенд из модулей. Слой — папка в `layers/`,
устроенная как маленький проект Nuxt: страницы, компоненты, composables, серверные маршруты.
Слой называется так же, как модуль бэкенда, с которым работает: `form` ↔ `form`.
Интерфейс — **Nuxt UI 4** на Tailwind 4.

## Что где лежит

| Где | Что | В репозитории |
|---|---|---|
| движок | API, формы, блог, страницы, SEO, карта сайта | этом, версиями |
| сайт | шапка, подвал, главная, свои страницы, цвета, перекрытые компоненты | своём у каждого сайта |
| контент | статьи, страницы, формы, заявки | не в git — в базе бэкенда сайта |

Личный кабинет — отдельная история: экраны у каждого проекта свои. Движок даёт для него
слой `user` — вход, регистрация, пароли, токены — без экранов. Пример кабинета — в демо-сайте.

## Структура

```
front/
├── nuxt.config.ts        # движок сайтов: слои core, form, page и Nuxt UI
├── app/                  # общее по умолчанию: обёртка, страница ошибки, каркас, стили, цвета
├── layers/
│   ├── core/             # клиент API с типами, разбор ошибок
│   ├── form/             # формы сайта и отправка заявок
│   ├── page/             # блог и страницы из админки, SEO, sitemap.xml
│   └── user/             # вход и токены для личного кабинета — в движок сайтов не входит
└── .playground/          # демо-сайт: на нём движок разрабатывают и проверяют
    ├── nuxt.config.ts    # подключает движок и слой user
    └── app/              # шапка, главная с формой, вход, регистрация, кабинет
```

| Слой | Модуль бэкенда | Описание |
|---|---|---|
| `core` | — | [layers/core/readme.md](layers/core/readme.md) |
| `form` | `form` | [layers/form/readme.md](layers/form/readme.md) |
| `page` | `page` | [layers/page/readme.md](layers/page/readme.md) |
| `user` | `user` | [layers/user/readme.md](layers/user/readme.md) |

## Запуск демо-сайта

```bash
npm install
cp .env.txt .playground/.env   # все настройки — с описанием в .env.txt
npm run dev                    # http://localhost:3000
```

Бэкенд — локальный `runserver` или dev-сервер. Порт фронта должен быть в `CORS_ALLOWED_ORIGINS`
бэкенда: иначе браузер заблокирует запросы к API, а выглядеть это будет как «нет связи».

| Команда | Что делает |
|---|---|
| `npm run dev` | демо-сайт с перезагрузкой |
| `npm run build` | сборка демо-сайта: `.playground/.output/` |
| `npm run test` | тесты слоёв (`layers/*/tests`) |
| `npm run typecheck` | проверка типов движка и демо-сайта |
| `npm run api:types` | типы API из кода `../back` — после каждого изменения API; нужен `back/.venv` |

На push в `dev` и `main` то же самое — `test`, `typecheck`, `build` — гоняет CI
(`.github/workflows/front.yml`): сломанный коммит видно до того, как сайт поставит его себе.

## Сайт на движке

В репозитории сайта — только своё. Движок подключается в `nuxt.config.ts` по тегу версии:

```ts
export default defineNuxtConfig({
  compatibilityDate: '2026-09-01',
  extends: [['gh:mcnickbronx/web-start/front#v2.4.0', { install: true }]],
})
```

- Nuxt скачает движок этой версии и поставит его зависимости (`install: true`).
  Репозиторий открытый, токен GitHub сборке не нужен. Движок из своего закрытого форка —
  токен с правом чтения в переменной `GIGET_AUTH`.
- **Версии `nuxt`, `vue`, `vue-router` у сайта — те же, что в `package.json` движка этой версии.**
  Движок проверен на своих: с другими сайт соберёт сочетание, которое никто не проверял.
  Сменил версию движка — сверить.
- **Обновить движок** — сменить тег и пересобрать. Перед сменой мажорной версии —
  прочитать [CHANGELOG.md](../CHANGELOG.md). Между выпусками — полный хеш коммита `main`
  вместо тега (`#bfddda7f…`), но не ветка: она меняется. Бэкенд сайта — на тот же хеш,
  раньше фронта ([порядок](../readme.md#версии)).
- `.env` сайта — по `.env.txt`: там все настройки движка с описанием (адреса бэкенда и сайта, открыт ли
  сайт для поиска, счётчик Метрики). Появилась новая — строкой туда же и в `.env.txt` шаблона сайта.

Как сайт делает себе свой вид, не теряя обновлений движка:
- **Своё целиком** — `app/layouts/default.vue` (шапка и подвал), `app/pages/index.vue`
  (главная), свои страницы в `app/pages/`.
- **Цвета и тексты** — `app/app.config.ts`: `ui.colors` (палитры Tailwind) и настройки слоёв,
  например заголовок ленты блога. Шрифты — CSS-переменными (`--font-sans`) в своём CSS.
  Списки в `app.config` (например, `page.sitemapPageList`) сайт дописывает к списку движка,
  а не заменяет.
- **Вид блога и формы** — файл с тем же именем в `app/components/`: `PageBlog` (лента),
  `PageFeed` (карточки), `PageArticle` (статья и отдельная страница), `PageCategoryMenu`, `FormTrap`.
- **Страницы движка не перекрывать.** В них логика: какие данные грузить, SEO, коды 404
  и 301. Перекрытая страница перестанет получать исправления. Нужно иначе — перекрывать
  компонент, а если не хватает настройки — добавить её в движок.
- **Перекрытый компонент — зона сайта:** исправления стандартного до него не дойдут.
  Поэтому перекрывать точечно.

## Версии

Фронт выходит одной версией с бэкендом — тегом репозитория `web-start`. Правила версий
и порядок выпуска — в [readme репозитория](../readme.md#версии), что изменилось —
в [CHANGELOG.md](../CHANGELOG.md).

«Договор» движка с сайтом — то, что описано в readme слоёв: composables, имена и свойства
компонентов, адреса страниц, настройки в `app.config`, переменные окружения. Их изменение —
мажорная версия. Остальное — функции из `utils`, внутренности composables — сайту видно без
`import`, но это внутреннее: меняется в любой версии, сайт на него не опирается. Нужно сайту —
описать в readme слоя, тогда это договор. Разметку стандартных компонентов можно улучшать
в минорных: сайт, которому важен свой вид, перекрывает компонент.

## Как устроены слои

- **Подключение.** Слои движка перечислены в корневом `nuxt.config.ts`. Страницы слоя
  становятся маршрутами, composables и компоненты доступны без `import`, серверные
  маршруты отвечают.
- **Перекрытие.** Файл сайта (`app/…`) важнее файла движка с тем же именем.
- **Зависимости.** Слой зависит только от `core` (и от `user`, если нужен вход). Слои
  друг друга не импортируют. Типы API — `import type { components } from '#api-types'`.

## Почему Nuxt UI

Выбирали из Nuxt UI 4 и PrimeVue — одни и те же экраны собрали на обеих библиотеках против
живого API.

- **Лицензия.** Nuxt UI — MIT. PrimeVue 5 без ключа показывает на каждой странице плашку
  «Invalid PrimeUI License», а бесплатный ключ действует год: забыли продлить — плашка
  появится на всех сайтах сразу. PrimeVue 4 — MIT, но больше не развивается: с выхода
  пятой версии обновлений нет.
- **Кода меньше.** Поле формы — один тег с подписью, ошибкой бэкенда и отметкой
  обязательности. На формах разница 15–25%, на таблицах — вровень.
- **Одна система стилей** — Tailwind. У PrimeVue поверх неё своя тема со своими слоями стилей.
- **Скорость** почти равная: на медленном телефоне Nuxt UI рисует первый экран на 0,2 с
  быстрее, страница не подвисает при загрузке.

Что теряем: таблицы с фильтрами по колонкам в PrimeVue есть готовые, здесь их собирать
самим. Вернуться на PrimeVue можно — логика живёт в слоях и от UI не зависит, переписать
придётся только экраны.
