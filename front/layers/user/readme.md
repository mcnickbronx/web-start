# Слой user
Как устроен слой · 22.10.2026

Кабинет: вход, регистрация с кодом из письма, сброс и смена пароля, профиль. Пара к модулю
`user` бэкенда. Зависит только от `core`.

## Как подключить

В движок сайтов слой не входит. Сайт с кабинетом добавляет его второй строкой `extends`
в `nuxt.config.ts`, с тем же тегом, что у движка:

```ts
extends: [
  ['gh:mcnickbronx/web-start/front#v2.4.0', { install: true }],
  'gh:mcnickbronx/web-start/front/layers/user#v2.4.0',
],
```

- **Без `{ install: true }`.** Своих пакетов у слоя нет, он берёт их у движка. С этим флагом Nuxt
  на каждой сборке запускает `npm install` в папке слоя, а npm, не найдя там `package.json`,
  берёт `package.json` сайта: заново ставит его пакеты и переписывает `package-lock.json`.
- **Тег — один на обе строки.** Клиент API и его типы слой берёт у движка: проверены вместе
  только слой и движок одной версии.
- **Экранов в слое нет** — образец в демо-сайте: [`.playground/app/pages/`](../../.playground/app/pages/) (`login.vue`, `register.vue`,
  `password-reset.vue`, `lk/`), каркас кабинета `layouts/lk.vue` и `utils/form-errors.ts`. Их копируют
  в `app/` сайта и переделывают под макет. В скопированном типы Nuxt UI — из `'#ui/types'`, а не из
  `'@nuxt/ui'`: этот пакет у сайта не свой, а движка, и `nuxt typecheck` сайта его не найдёт.
- Адрес сайта — в `CORS_ALLOWED_ORIGINS` бэкенда (ниже, «Что стоит знать»).

## Как пользоваться

```ts
const auth = useAuth()
const { error } = await auth.login({ email, password })   // error.message, error.fieldMap
auth.user.value?.email
```

| Действие | Что делает |
|---|---|
| `login` | вход |
| `register` → `activate` | регистрация: пользователь неактивен, код приходит на почту; код — и сразу вход |
| `resendCode` | выслать код ещё раз (по умолчанию не чаще раза в минуту) |
| `requestPasswordReset` → `confirmPasswordReset` | забыли пароль: код на почту, новый пароль по коду — и сразу вход |
| `changePassword` | смена пароля: старые токены на всех устройствах перестают работать |
| `loadMe`, `updateProfile` | профиль |
| `logout` | выход на этом устройстве — его токены перестают работать сразу |
| `logoutAll` | выход на всех устройствах |
| `sessionList`, `endSession` | где я вошёл; выйти на другом устройстве (пример — профиль в демо-сайте) |

Страница только для вошедших — под `/lk` и с `definePageMeta({ middleware: 'auth' })`.
Гостя отправит на `/login?next=<адрес>`, после входа — обратно.

## Где живут токены

- **Access** (по умолчанию сутки) — только в памяти вкладки. Закрыли вкладку — он пропал.
- **Refresh** (по умолчанию 30 дней) — в куке `httpOnly`, её ставит сам бэкенд при входе: скрипты страницы
  её не видят, и украсть её через внедрённый скрипт нельзя. Браузер шлёт её только
  на `/api/user/refresh`.

Вход, активация и пароли идут из браузера прямо в API, как заявки. Поэтому лимит частоты
на вход (Traefik, 10 в минуту) считается по адресу посетителя, а не один на всех: через сервер
сайта все входы пришли бы с одного адреса, и любой, кто долбит вход, закрыл бы его всем.

После перезагрузки страницы вход восстанавливается по куке, когда посетитель заходит
в кабинет (middleware `auth`). Публичные страницы о входе не знают — гостям лишних запросов нет.

Кабинет рендерится только в браузере: сервер Nuxt токена не знает и отрисовать кабинет не может.
Правило `/lk/**` с `ssr: false` задано в `nuxt.config.ts` слоя — сайту добавлять его не нужно.

## Что стоит знать

- **Выход срабатывает сразу.** Каждый вход — сессия на бэкенде, токены живут, пока жива сессия:
  выход, «выйти на всех устройствах» и выход на другом устройстве из списка гасят токены
  немедленно, а не когда истечёт access.
- **Выйти без бэкенда нельзя.** Куку refresh скрипт страницы не видит и стереть не может — это
  делает бэкенд. Поэтому `logout()` и `logoutAll()` при сбое вход не сбрасывают и возвращают
  ошибку: её показать, выход повторить (образец — кабинет демо-сайта). Иначе на чужом компьютере
  следующий, кто откроет кабинет, войдёт по оставшейся куке.
- **Бэкенд — на поддомене сайта** (`back.site.ru` для `site.ru`): куку с другого домена
  браузер не пришлёт, и после перезагрузки придётся входить заново.
- **Адрес сайта должен быть в `CORS_ALLOWED_ORIGINS` бэкенда**, иначе браузер заблокирует
  запросы к API. Локально — порт фронта: `http://localhost:3000`.
- Флаг `Secure` у куки — как у куки сессии админки: на сервере есть, локально (`DEBUG=True`,
  HTTP) — нет.

## Шпаргалка

- `useAuth()` — всё про вход и профиль, ответы — `{ data }` или `{ error }`.
- Кабинет — `/lk/*` с `middleware: 'auth'`.
- Токены не класть в localStorage: access — память, refresh — httpOnly-кука бэкенда.
