# CLAUDE.md

Репозиторий `web-start`: бэкенд в `back/` (Django + FastAPI + Tortoise), фронт в `front/`
(Nuxt 4, движок сайтов). Что это и как устроено — [readme.ru.md](readme.ru.md).

У каждой части свои правила: `back/CLAUDE.md` и `front/CLAUDE.md`. Перед работой в части —
её CLAUDE.md и readme. Команды запускать из папки части.

## Общее
- Избегай оверинжиниринга: проще и меньше кода.
- Лучше честное «нет» / «не знаю» / «не нашёл», чем правдоподобный ответ ради вида работы.
  Не выдавай слабое за сильное, догадки за факты, пересказ за проверку.
- Одна версия на обе части — тег репозитория. Изменение, которое почувствуют сайты (API,
  настройки, миграции, «договор» фронта с сайтом), — строкой в `CHANGELOG.md`, раздел
  «Не выпущено». Версии и теги ставит разработчик.
- Парное изменение — модуль бэкенда и слой фронта с тем же именем — одним коммитом:
  тогда любая версия совместима сама с собой.
- Изменилось API бэкенда — `npm run api:types` во `front/` (схема — из кода `back/`, база не нужна)
  и новые типы в тот же коммит.
- git — предлагай команды, не выполняй сам.

## Документация
Обновляется в том же коммите, что и код. **Одно правило — одно место:** объяснение для человека —
в одном документе, остальные ставят ссылку; правило для ассистента — строкой в CLAUDE.md той части,
где оно действует, общее для обеих частей — только здесь. Как писать — [back/docs/writing-docs.md](back/docs/writing-docs.md).
- Документация на русском. Исключение — корневой `readme.md`: короткий вход на английском для
  открытого репозитория. Поменялось то, что в нём есть (роли, стек, запуск, структура), — поправить
  и его, и `readme.ru.md`.
- Репозиторий открытый: в коде и доках — без адресов серверов, имён сайтов клиентов, личных почт
  и ключей. В примерах — `example.com`.

## Процесс работы
Причины — [back/docs/rules-ai.md](back/docs/rules-ai.md).
- При первом сообщении кратко напомнить: ревью глазами, частые локальные коммиты,
  squash перед пушем, в конце — ревью кода, тесты, документация.
- Когда пишут «готово», «закончил», «всё» — предложить: ревью кода (с номером коммита
  и чистым контекстом `/clear`), прогон тестов локально, описание сделанного.
