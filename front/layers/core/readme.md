# Слой core
Как устроен слой · 25.10.2026

Связь с API бэкенда: клиент с типами и разбор ошибок, счётчик Яндекс Метрики, canonical и Open Graph
по умолчанию, SEO страницы одной строкой.
От него зависят все слои, сам он не зависит ни от кого.

## Запросы к API

```ts
const api = useApi()
const { data, error } = await apiRequest(api.GET('/api/page/list', { params: { query: { row: 10 } } }))
```

- **Адреса, параметры и ответы типизированы** по `openapi.json` бэкенда: опечатка в адресе
  или поле — ошибка при проверке типов, а не 404 у пользователя.
- **Типы в своём коде** — `import type { components } from '#api-types'`, схема ответа —
  `components['schemas']['PageListOut']`.
- **Типы генерирует `npm run api:types`** в `app/types/api.d.ts` — из кода бэкенда в `../back`
  того же коммита (`manage.py export_openapi` через `back/.venv`, база не нужна), а не с сервера:
  сайт ставит бэкенд и движок одной версии, и типы движка должны описывать бэкенд своего тега.
  Изменилось API — перегенерировать и закоммитить вместе с правкой. Руками файл не править.
- **Токен подставляется сам.** На 401 клиент один раз обновляет токен и повторяет запрос —
  если подключён слой `user`. Без него 401 просто возвращается.
- **Адрес бэкенда** — `NUXT_PUBLIC_API_BASE` в `.env`.
- **Таймаут — 60 секунд.** Страницы сайта грузят данные при рендере на сервере Nuxt:
  без таймаута зависший бэкенд подвесил бы и их.

## Ошибки

`apiRequest` не бросает исключений: всегда `{ data }` или `{ error }`. Ошибка одна
на все случаи — `ApiError`:

- `message` — текст для пользователя, показывать как есть;
- `fieldMap` — ошибки по полям (`{ phone: 'Обязательное поле' }`), показывать под полем;
- `status` — код ответа, `0` — ответа не было.

| Что случилось | Что в `message` |
|---|---|
| 422 — данные не прошли проверку | текст бэкенда, по полям — в `fieldMap` |
| 406 — бизнес-ошибка (капча, форма устарела…) | текст бэкенда |
| 401, 403, 404 | текст бэкенда или общий по коду |
| 429 — лимит частоты на прокси | «Слишком много попыток…» |
| 500, 502 | «Сервер не смог обработать запрос…» — подробности пользователю не нужны |
| нет ответа (сеть, сервер лежит) | «Нет связи с сервером…» |

## Яндекс Метрика

Счётчик включается номером в `NUXT_PUBLIC_METRIKA_ID` — только он, код счётчика вставлять
не нужно. Пусто — на сайт не грузится ничего. Номер читается при запуске: на сервере сменить
`.env` и пересоздать контейнер, пересборка не нужна.

- **Переходы внутри сайта** Метрика сама не видит — сайт на Vue не перезагружает страницу.
  Слой отправляет просмотр, когда новая страница отрисована; якоря (`/#tarify`) — не переход.
- **Вебвизор, карта кликов, внешние ссылки, точный показатель отказов, электронная коммерция**
  (`dataLayer`) — включены, как в коде счётчика из кабинета Метрики.
- **Цели** — `useMetrika().reachGoal('имя')`, без счётчика вызов пустой. Слой `form` сам
  отправляет цель `form_<код формы>` на каждую заявку.
- **Посетитель Метрики** уходит в заявку (`ym_client_id` из куки `_ym_uid`, слой `form`):
  по заявке в админке видно, откуда человек пришёл, и визит находится в Метрике.

## Уведомление о cookie

Внизу экрана, пока посетитель не ответит: «Принять» или «Отклонить».
«Отклонить» выключает Метрику: со следующей загрузки она не грузится, а переходы и цели
перестают уходить сразу. Ответ помнит браузер. Это про cookie, а не согласие на обработку
данных заявки: такого согласия в шаблоне нет. Как его оформить — решает юрист: с 01.09.2025 согласие
оформляется отдельно от других документов (152-ФЗ ст. 9 ч. 1); делает сайт
([что шаблон хранит о человеке](../../../back/docs/personal-data.md)). Настройки — в `app/app.config.ts` сайта:

```ts
cookieNotice: { policyUrl: 'https://…/policy.pdf' }   // ссылка на политику; пусто — без ссылки
cookieNotice: { isEnabled: false }                    // сайт без cookie — не показывать
```

Свой вид — `app/components/CookieNotice.vue` сайта. Всё, что сайт может поменять, —
[таблица](../../readme.md#что-сайт-может-поменять).

## SEO по умолчанию

На каждой странице сайта — `canonical` и `og:url` с адресом страницы без параметров, `og:type`
(`website`) и `og:locale` (`ru_RU`). Адрес с метками рекламы (`?utm_source=…`, `yclid`) — та же
страница: поисковики и соцсети не заводят дублей. Сайту ничего делать не нужно. Страница со своим
SEO (`useSeo`, ниже) перекрывает умолчание, тег остаётся один.

**Ссылка в мессенджере — с названием и картинкой**, если сайт задал их в `app/app.config.ts`:

```ts
seo: { siteName: 'Пример', image: '/images/og.png' }   // og:site_name и og:image; пусто — без тега
```

Картинка — 1200×630 в `public/` сайта или полный адрес; путь из `public/` движок превращает в полный адрес
от адреса сайта — относительный мессенджеры не понимают. Это картинка по умолчанию: страница со своей
(статья с картинкой из админки, `useSeoMeta({ ogImage })` сайта) показывает свою.

**Адрес сайта — `NUXT_PUBLIC_SITE_URL`.** От него строятся canonical, Open Graph и карта сайта.
Не задан — берётся из запроса, но за прокси протокол может оказаться `http`. На сервере
задавать обязательно.

## SEO своей страницы

Каталог, карточка товара, вход в кабинет, своя страница сайта — SEO одной строкой в `<script setup>`
страницы. Слой `page` для этого не нужен: модуль магазина или кабинета не зависит от блога.

```ts
const route = useRoute()
useSeo({ title: 'Каталог', description: 'Товары магазина', page: parsePageNumber(route.query.page) })
useSeo({ title: 'Вход', isIndexed: false })   // вход и регистрация поиску не нужны
```

- **Что ставит:** заголовок вкладки, описание, `canonical`, Open Graph (`og:title`, `og:description`,
  `og:url`, `og:image` — если передана `image`), с `isIndexed: false` — `robots: noindex`.
- **Адрес — страница без параметров**, как у SEO по умолчанию: метки рекламы в canonical не попадают.
  Хост — всегда сайта, даже если путь похож на чужой домен (`//…`). Нужен другой адрес — `path`.
- **Лента по страницам** — `page`: со второй страницы номер в адресе (`/catalog?page=2`), у первой его нет.
  Для поисковика вторая страница ленты — другая страница, а адрес с метками — та же.
  `parsePageNumber` берёт номер из `?page=`: мусор, ноль и отрицательные — первая страница.

## Шпаргалка

- Запрос — `apiRequest(useApi().GET(...))`, ответ — `{ data }` или `{ error }`.
- Изменилось API бэкенда — `npm run api:types` и коммит.
- `error.message` — пользователю, `error.fieldMap` — под полями.
- На сервере — `NUXT_PUBLIC_SITE_URL`: canonical и Open Graph на каждой странице.
- SEO своей страницы — `useSeo({ title, description, page, isIndexed })`; номер ленты — `parsePageNumber(route.query.page)`.
