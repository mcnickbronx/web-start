# Модуль «Живые события»
Как устроен модуль · 24.10.2026

Сервер сам сообщает открытой странице, что что-то произошло: пришло сообщение в чат, заказ
оплачен, отчёт готов. Без этого кабинету пришлось бы спрашивать сервер каждые несколько секунд.
Страница держит одно соединение WebSocket, сервис бэкенда шлёт в него событие пользователю —
во все его открытые вкладки, на любом устройстве.

Модуль необязательный: моделей, миграций и админки у него нет. Событие получает только тот,
кто вошёл, — по access-токену, как в остальном API. Сейчас событие адресуется одному
пользователю; группам (вся компания) — нет.

## Как подключиться

Адрес — `/api/live/ws` (на сервере — `wss://`). Swagger WebSocket не показывает, поэтому
протокол описан здесь. Сообщения — JSON-объекты с полем `type`.

1. Страница открывает соединение и первым сообщением шлёт токен:
   `{"type": "auth", "token": "<access>"}`.
2. Токен годный — ответ `{"type": "ready"}`: с этого момента приходят события.
3. Дальше приходят события — `{"type": "…", …}`, их состав задаёт модуль, который их шлёт.
   На `{"type": "ping"}` сервер отвечает `{"type": "pong"}`, остальное от страницы пропускает.

Сервер закрывает соединение кодом **4401**, если первое сообщение не пришло за 5 секунд, оно
не JSON-объект, в нём нет токена, токен негодный, просрочен, это refresh, а не access, сессию
закрыли или пользователь выключен. Странице на 4401 — обновить access-токен и подключиться
заново; второй 4401 подряд — нужен вход.

**Почему токен — сообщением, а не в адресе.** Адрес вместе с параметрами попадает в журнал
доступа: uvicorn пишет `"WebSocket /api/live/ws?token=…"` как есть. Токен в сообщении в журнал
не попадает, а чужой сайт, открыв соединение, без токена ничего не получит.

## Как отправить событие

Из сервиса API или фоновой задачи:

```python
from live import hub

await hub.send(user.id, {"type": "order_paid", "order_id": order.id})
```

Из админки и команд `manage.py` — тот же сервис через `.sync(...)`, как любой
[асинхронный сервис](../core/readme.md#асинхронный-сервис-из-админки):
`hub.send.sync(order.user_id, {"type": "order_paid", "order_id": order.id})`.

- Событие — словарь, который пишется в JSON: строки, числа, списки, словари. `Decimal` и даты
  `json` не пишет (`TypeError`) — деньги и даты кладите строкой, как в ответах API.
- Событие не хранится. Открытой вкладки нет — событие пропало; соединение оборвалось
  и переподключается — события за это время не придут. Поэтому событие — сигнал «что-то
  изменилось», а данные страница берёт из API: после события и после каждого
  переподключения.
- `send` не сообщает о доставке и не падает, если Redis недоступен: в журнал уходит
  предупреждение, основное действие (оплата, сохранение) продолжается.
- Модуль, который шлёт события, зависит от `live`, как `form` от `user`: убрали `live` —
  уберите и вызовы `hub.send`.

## Несколько процессов: Redis

Соединение вкладки живёт в одном процессе API, а событие может родиться в другом: в соседнем
процессе API, в админке (в профиле full — свой контейнер) или в воркере задач.

- **Без `REDIS_URL`** событие уходит прямо в соединения этого процесса. Так работает профиль
  light с одним процессом API (`API_WORKERS=1`): API, админка и задачи — в нём.
- **С `REDIS_URL`** событие уходит в канал Redis `live`, а каждый процесс API отдаёт его своим
  соединениям. Нужен, когда процессов API больше одного, и в профиле full — там он задан
  ([деплой](../../docs/deploy.md)).
  Слушать канал процесс начинает с первым соединением. Связь с Redis пропала — предупреждение
  в журнал и новая попытка через 1–5 секунд, вкладки остаются подключёнными, но события
  за это время теряются.

## Лимит Traefik

Traefik пропускает с одного адреса не больше 150 запросов одновременно
([деплой](../../docs/deploy.md#ограничение-частоты-запросов)), а открытое соединение —
это запрос, который длится, пока открыта вкладка. Офис за одним адресом с десятками
открытых вкладок упрётся в этот лимит, и сайт начнёт отвечать 429 на всё. Поэтому:
соединение — одно на вкладку, а без токена оно живёт не дольше 5 секунд.

## Как убрать модуль

Строку `"live"` из `INSTALLED_APPS` в `project/settings.py`, папку `live/` и вызовы `hub.send`
в своих модулях. Миграций нет — `migrate live zero` не нужен.

## Шпаргалка

- Подключение: `/api/live/ws`, первым сообщением `{"type": "auth", "token": "<access>"}`, ответ `ready`; 4401 — нужен новый токен или вход.
- Событие: `await hub.send(user_id, {"type": "…"})`, из админки и команд — `hub.send.sync(...)`.
- Событие не хранится: после него и после переподключения страница перечитывает данные из API.
- Больше одного процесса API и профиль full — нужен `REDIS_URL`.
- Одно соединение на вкладку: каждое занимает место в лимите Traefik.
