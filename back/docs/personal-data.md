# Что шаблон хранит о человеке
Для политики сайта и ответа на запрос человека · 07.11.2026

Для программиста, которому юрист прислал вопрос «что сайт собирает», и для юриста, который пишет
политику сайта: что о посетителе и пользователе хранят модули и слои шаблона, где, сколько, кто видит
и как удалить. Свои модели и формы проекта сюда не входят — их проект дописывает сам.

Это не юридическая консультация. Нормы названы номером статьи 152-ФЗ, без толкований; что из этого
персональные данные и что писать в политике, решает юрист проекта. Политика публикуется на страницах
сайта, где собирают данные (ст. 18.1 ч. 2), — сюда смотреть, чтобы ничего не пропустить.

## На сервере

| Что | Где лежит | Сколько хранится | Кто видит | Как удаляется |
|---|---|---|---|---|
| **Заявка** (модуль `form`): имя, телефон — как набрал человек, email, сообщение, дополнительные поля формы; страница отправки, IP, браузер; откуда пришёл на сайт — сайт-источник, первая страница визита, метки рекламы (`utm_*`, `yclid`, `gclid`), ID посетителя в Яндекс Метрике; если вошёл — его аккаунт. Даты создания, изменения и отправки письма (`date_add`, `date_modified`, `date_email_sent`) | база | пока не удалят вручную: уборки по сроку нет | в админке — кто может смотреть заявки; выгрузка в Excel | в админке, по одной или «Удалить выбранные» — вместе с файлами и историей |
| **Отметка согласия**: серверная дата `date_consent` и проверенный IP `consent_ip`; у новой записи без явного True и у старых строк — NULL. Повторы регистрации — ниже; правило и пределы — [ядро](../app/core/readme.md#согласие) | база, в самой заявке или пользователе | пока существует запись | админка, только чтение; в публичном профиле нет | вместе с соответствующей записью |
| **Файлы заявки** — содержимое, исходное имя, размер и дата загрузки | папка `private/form/`, по прямой ссылке не открывается | пока есть заявка; неприложенные отбирает `clear_form_files` при возрасте больше `FORM_FILE_ORPHAN_HOURS` (24 ч), расписание — ежедневно в 04:30 по Москве. До успешного запуска лежат дольше, при пропусках — без гарантии верхнего срока | админка (кто может смотреть заявки); из API — только автор заявки, если отправлял её вошедшим | с заявкой — и запись, и файл с диска; ничьи — команда `clear_form_files` |
| **История заявки** — смены статуса, время изменения и кто менял | база | пока есть заявка | админка, карточка заявки | с заявкой |
| **Письмо о заявке**: имя, телефон, email, сообщение, дополнительные поля, страница, канал и метки `utm_source`, `utm_campaign`, названия файлов (сами файлы — нет). С галкой формы «Техническая информация в письме» — ещё время до секунды, первая страница визита, сайт-источник, все метки, ID в Метрике, IP, браузер словами | ящики из поля формы «Кому отправлять» | как хранит почта получателей | получатели письма | вне шаблона |
| **Пользователь** (модуль `user`): email, имя, фамилия, хеш пароля (сам пароль не хранится), текущий код подтверждения и число попыток. Даты регистрации (`date_joined`), последнего входа (`last_login`), смены пароля (`password_changed_at`), выдачи текущего кода (`confirmation_code_created_at`, не подтверждение доставки письма) | база | пока не удалят вручную; неподтверждённые регистрации тоже | админка (поиск по email, имени, фамилии); сам человек — свой публичный профиль в кабинете, без служебных полей | только в админке: сам удалить аккаунт человек не может. Сессии уходят с ним, **заявки остаются** — см. ниже |
| **Сессии входа**: IP и браузер в момент входа, даты входа (`date_add`) и продления входа через refresh (`date_used`), а не каждого просмотра страницы | база | до завершения сессии; не продлевалась дольше `USER_JWT_REFRESH_LIFETIME_DAYS` (30 дней) — удаляется при следующем входе этого пользователя, а если он не вернётся — лежит | сам человек — «где я вошёл»; админка — в карточке пользователя | выход, «выйти на всех устройствах», выход с другого устройства, смена и сброс пароля через API, удаление пользователя |

Подтверждение задачи не запрашивает удаление её содержимого; подробности и границы проверки — ниже | администратор сервера | срок и фактическое удаление содержимого нужно проверять отдельно; недействительность кода через 30 минут не означает его стирания |
| **Журнал** (модуль `log`): модули пишут номер заявки и код формы («Заявка №812 (callback) с сайта»), без имён и телефонов. Ошибки и трейсбеки могут содержать данные человека | база | порог отбора — `LOG_KEEP_DAYS` (90 суток), но фактическое хранение дольше до успешной уборки; точная граница — ниже | админка, «Журнал» | `clear_log`, по расписанию ежедневно в 04:00 по Москве; вручную в админке |

| **Бэкапы и копии**: база со всем, что выше, и файлы `private/` | бэкапы сервера: папка проекта с `private/` ([деплой](deploy.md#файлы)), база — как настроил администратор; копия боевой базы у разработчика ([команды](commands.md#скопировать-боевую-базу-в-локальную)) | до срока бэкапов сервера; копия — пока её не удалят | администратор; разработчик с копией | удалённое в базе живёт в бэкапах до их срока |

У заявки и пользователя хранится одна текущая отметка согласия, а не история каждого согласия.
При успешном повторе неподтверждённой регистрации без нового True прежние дата/IP сохраняются;
успешный True обновляет их. Отказ по интервалу выдачи кода и сбой очереди не меняют отметку.
При включённом требовании согласия повтор требует текущий True, даже если отметка уже есть.
Проверяют `user/tests/test_consent.py`, `test_successful_repeat_preserves_or_updates_fact_and_never_name`
и `test_interval_and_queue_failure_do_not_rewrite_fact`; для заявки — `form/tests/test_consent.py`.

`clear_log` удаляет записи **строго раньше** времени запуска минус `LOG_KEEP_DAYS` суток.
Запись точно на границе остаётся; это сравнение времени, а не календарных дат или гарантированные
90 суток хранения. Например, при запуске 07.11.2026 в 04:00 по Москве граница — 09.08.2026
в 04:00 по Москве. До следующего успешного запуска запись продолжает храниться; остановленный
cron или ошибка команды продлевают срок. Границу на PostgreSQL держит `log/tests/test_retention.py`,
`test_command_keeps_exact_cutoff_and_newer_rows`. Расписание использует `CRON_TZ=Europe/Moscow`,
в базе даты обрабатываются как моменты времени UTC.

Для Redis проверены сериализация email/кода и команды брокера: добавление содержимого с приблизительным
пределом объёма и подтверждение без команды стирания. Держит `core/tests/test_broker_payload.py`,
`test_code_payload_is_serialized_and_ack_does_not_request_erasure`. Это проверка протокола без запущенного
Redis; реальный срок содержимого, сохранность AOF и удаление копий на диске из неё не следуют.
Журнал админки и его ограничения держит `form/tests/test_admin_data.py`,
`test_recent_actions_are_own_but_record_history_includes_other_staff` и
`test_admin_deletion_keeps_user_email_in_log_and_unlinks_request`.

## Куда уходит с сервера и из браузера

- **Почта** — письмо о заявке на адреса формы, письмо с кодом — человеку на его email. Через почтовый
  сервер из `EMAIL_*` в `.env` проекта.
- **Telegram** — если заданы `TELEGRAM_TOKEN` и «Чаты Telegram» у формы, для заявок вне спама.
  Базовое уведомление передаёт номер заявки, название формы, канал и число файлов.
  Галка «Контакты в Telegram» добавляет имя, телефон, email, сообщение и дополнительные поля.
  Отдельные технические поля и отметка согласия автоматически не добавляются; файлы и их названия
  не передаются. Произвольный текст сообщения, дополнительных полей и названия формы сам может
  содержать адрес, IP или другие данные — галка не обезличивает текст. Настройки, состав и ограничения —
  [модуль form](../app/form/readme.md#telegram). Сообщение оказывается у внешнего получателя;
  шаблон не управляет его хранением и удалением, удаление заявки сообщение не отзывает.
- **Яндекс Метрика** — если задан `NUXT_PUBLIC_METRIKA_ID`: счётчик в браузере посетителя, с Вебвизором
  и картой кликов ([слой core](../../front/layers/core/readme.md#яндекс-метрика)). Грузится сразу при
  открытии сайта, до ответа на уведомление о cookie; «Отклонить» выключает её со следующей загрузки.
  Что записывает Вебвизор и что прячет сам — [справка Яндекса](https://yandex.ru/support/metrica/ru/webvisor/settings).
- **Яндекс SmartCaptcha** — если `FORM_CAPTCHA_PROVIDER=yandex` и у формы «Капча»: виджет Яндекса в браузере,
  а бэкенд при проверке отправляет Яндексу токен виджета и IP посетителя ([модуль form](../app/form/readme.md#защита-от-ботов)).

Это карта известных каналов шаблона, а не запрет других вызовов. Необязательное `core.ai`
может передавать сообщения выбранному внешнему сервису при явном вызове и настроенном ключе;
автоматической передачи заявок туда здесь нет. Свои интеграции и состав отправляемых данных
проект добавляет сам. Фактические настройки, сроки, география хранения и удаление у внешних
получателей из исходников шаблона не определяются.

## В браузере посетителя

- `cookie-choice` в localStorage — ответ на уведомление о cookie: «Принять» или «Отклонить» (слой `core`).
- `form:visit` в localStorage — сайт-источник, первая страница визита с параметрами и время. Новый заход
  с другого сайта или с метками его перезаписывает, прямой — нет, пока запись моложе 30 дней. Уходит
  с заявкой (слой `form`).
- Кука `refresh` — вход в кабинет: недоступна скриптам страницы, отправляется только на `/api/user/refresh`,
  живёт срок входа. Сам access-токен — только в памяти вкладки (слой `user`).
- Куки Метрики ставит сам счётчик Яндекса; из куки `_ym_uid` слой `form` берёт ID посетителя для заявки.

## Человек просит «что у вас обо мне» или «удалите»

Сроки ответа и удаления — 152-ФЗ, ст. 20 и 21. Что можно сделать в шаблоне сейчас:

1. **Найти заявки.** Админка → «Заявки», поиск по имени, телефону, email и сообщению.
   Поиск смешанного ASCII-регистра email проверен для заявок и пользователей на PostgreSQL:
   `MiXeD.Reader@example.com` находится по `mixed.reader@EXAMPLE.COM` и `MIXED.READER`.
   Держит `form/tests/test_admin_data.py`, `test_email_search_finds_mixed_ascii_case_in_requests_and_users`;
   это не обещание одинакового преобразования любого Unicode-текста.
   Телефон хранится так, как его набрали, поэтому искать **частями через пробел**: `999 123` находит
   и `+7 (999) 123-45-67`, и `89991234567`, и `8 999 123 45 67`, и `+79991234567`. Целый номер находит
   только записанный похоже: из этих четырёх `89991234567` найдёт одну заявку, `9991234567` — две.
2. **Найти аккаунт.** «Пользователи», поиск по email, имени, фамилии; в карточке — его сессии.
3. **Ответить**, что хранится, — собрать руками по таблице выше: выгрузки «всё о человеке» нет.
4. **Удалить.**
   - Заявки — отметить найденные, «Удалить выбранные»: уходят заявки, их файлы с диска и история.
   - Аккаунт — удалить пользователя: уходят он и его сессии. **Заявки остаются** — с именем, телефоном, IP
     и файлами, только без связи с аккаунтом. Их удалить отдельно, шагом выше.
   - **Проверить оставшиеся копии и следы отдельно:** журнал действий с email удалённого, почту и Telegram
     получателей, содержимое очереди Redis, записи журнала с текстом ошибки, логи контейнеров,
     бэкапы и копии базы у разработчиков, данные Метрики у Яндекса. Удаление из основной базы
     не стирает их; срок, доступ и порядок удаления различаются — см. таблицу выше.

## Чего в шаблоне нет — делает проект

- **Текста согласия и его редакций.** Есть опциональная проверка и отметка даты/IP, но нет связи с документом
  и гарантии юридической достаточности: [правило и пределы](../app/core/readme.md#согласие). Текст обеспечивает проект; [учебные заготовки и подключение](../../front/layers/core/readme.md#подключить-заготовки-к-своему-сайту).
- **Текста политики.** Его пишет юрист проекта; ссылку на неё сайт задаёт в `cookieNotice.policyUrl`
  ([слой core](../../front/layers/core/readme.md#уведомление-о-cookie)), по умолчанию её нет.
- **Срока хранения** заявок и неподтверждённых регистраций — лежат, пока их не удалят руками.
- **Обезличивания** — заявку можно только удалить целиком, а с ней уходят канал и метки для отчётов по рекламе.
- **Удаления аккаунта самим человеком** — только сотрудник в админке.
- **Поиска по цифрам телефона** в любом виде записи — только частями, как выше.
- **Журнала доступа** — кто из сотрудников открывал заявку, не записывается; история заявки — только смены статуса.
- **Метрики только после согласия** — счётчик грузится до ответа на уведомление о cookie.

## Шпаргалка

- Юрист спрашивает, что собирает сайт, — ссылка на эту страницу плюс то, что проект дописал сам.
- У заявок и пользователей автоматического срока нет; пороги журнала и ничьих файлов не гарантируют момент удаления.
- Удалили аккаунт — заявки человека остаются: найти по email и телефону частями и удалить отдельно.
- Почта, Telegram, Redis, журналы и бэкапы требуют отдельной проверки; удаление заявки не отзывает внешние копии.
- Текст согласия, сроки хранения и обезличивание обеспечивает проект; дата/IP — [опциональная отметка](../app/core/readme.md#согласие).
